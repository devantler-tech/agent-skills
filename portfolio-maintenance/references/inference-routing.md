# Delegation under an inference-routing contract

Use this procedure only when the consumer declares **Inference routing** and the selected work needs
delegation or escalation. The consumer supplies model assignments and operational limits; the
`portfolio-maintenance` skill's mandatory survey, trust, ownership, and promotion gates remain binding.

Delegate only a coherent, independently verifiable deliverable when expected savings exceed
instruction/history loading, tool use, parent integration, retries, and escalation. Keep deterministic
lint, formatting, tests, and Git commands in the owning task. A new model session is not required for
each sub-skill. Preserve required instructions; a short handoff does not bound automatically injected
history or preloaded skills.

**One live delivery owner per work item.** The owner manages the claim and PR lifecycle, integrates
child results, and verifies the complete promotion gate. Each active builder gets a physically isolated
working copy and explicit non-overlapping scope; serialize coupled changes even when their paths
differ. Read-only children need verified restrictions across every exposed tool, including shell and
MCP access. A role name or prompt does not establish that boundary. Consumer survey overrides still
apply; unavailable delegated enforcement retains the supported inline path without skipping discovery.

Give each child a bounded task packet: repository and immutable base revision; work item and live owner;
contract and routing-policy revisions; permitted paths and tools; acceptance checks; execution and
escalation bounds; and the evidence needed to resume. The child returns its result revision, checks
and outcomes, unresolved findings, and a complete/partial/blocked status. It does not independently
publish or merge the work. The owner verifies the actual result rather than trusting a completion
message. Rebind ownership before resumed mutations and stop the former writer before a handoff;
passing context to another runtime does not transfer ownership or subscription entitlement.

Escalate only on the consumer's declared failure evidence or direct task classification. Carry the
failed checks and distinct attempted hypotheses forward. Authentication, permission, quota, tool,
ownership, and missing-authority failures need operational recovery or a decision, not a larger model.
Never widen billing, model, tool, or concurrency limits during recovery. Retain the parent/child attempt
chain and measured context costs through the consumer's telemetry for `agent-improvement`.
